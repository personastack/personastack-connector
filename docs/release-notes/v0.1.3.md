# PersonaStack Connector v0.1.3

## Supported OS/arch

- macOS `darwin/amd64` and `darwin/arm64` archives.
- Linux `linux/amd64` and `linux/arm64` archives, `.deb`, and `.rpm` packages.
- Windows `windows/amd64` archive.

## Runtime caveats

- OpenClaw pairing now collects operator credentials locally through the Connector CLI or local environment only.
- Browser setup surfaces must not collect OpenClaw operator tokens, passwords, or device credentials.
- Pairing configures PersonaStack MCP access by default; MCP repair remains an advanced local command.
- Full wakeable status still requires authenticated bridge connectivity, local runtime health, native MCP verification, and wake probe success.
- Windows archives are covered by the release checksum and manifest sigstore bundles; Authenticode signing is applied only when the release environment provides the Windows signing certificate.

## Upgrade

- Install the v0.1.3 package or archive for the local OS and architecture.
- Re-run the PersonaStack pairing command shown in the external persona setup flow when creating a new binding.
- Existing OpenClaw users should provide credentials locally with `--openclaw-token`, `--openclaw-password`, `--openclaw-device-token`, or the matching `OPENCLAW_GATEWAY_*` environment variable.

## Rollback

- Reinstall the previous known-good Connector package or archive.
- In PersonaStack admin release metadata, reactivate the previous semver if user setup flows must stop recommending v0.1.3.
- Existing local bindings can remain paired unless the rollback target lacks required protocol support.
