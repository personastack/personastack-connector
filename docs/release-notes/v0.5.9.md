# PersonaStack Connector v0.5.9

Fixes Hermes profile installs so named profiles use their configured Hermes
home instead of falling back to `$HOME/.hermes` or creating nested Hermes
directories.

## Supported OS/arch

- macOS: `darwin/amd64`, `darwin/arm64`
- Linux archives: `linux/amd64`, `linux/arm64`
- Linux packages: `.deb` and `.rpm` for `amd64` and `arm64`

## Runtime caveats

- Hermes bindings can now store an explicit profile home with `--hermes-home`.
- Hermes MCP setup, repair, API-server verification, gateway startup, and
  generated services all use the same resolved Hermes home.
- The default Hermes path remains `$HOME/.hermes` when no explicit profile home
  or `HERMES_HOME` environment value is configured.
- OpenClaw native MCP behavior is unchanged.

## Upgrade

- Upgrade through Homebrew on macOS or the published Linux archive/package for
  your OS and architecture.
- For named Hermes profiles, run `personastack-connector runtime hermes configure
  --hermes-home /absolute/path/to/profile` or pair with `--hermes-home`, then run
  `personastack-connector mcp repair`.
- Restart the Connector service after replacing the binary or updating the
  stored Hermes profile home.

## Rollback

- Reinstall v0.5.8 from the GitHub release assets or Homebrew formula history.
- Restart the Connector service after rollback.
